==================================================
2. IMPORTANT BUSINESS RULE
==================================================

There are TWO different concepts:

A) REQUEST TO LOAD A VEHICLE
B) ACTUAL WAREHOUSE HANDOFF / LOADING

They must NOT be treated as the same event.

Agent can request/prepare a vehicle loading list.

Warehouse stock must NOT be deducted merely because the agent pressed "Finish".

Actual warehouse stock movement happens only when the warehouse operator confirms the physical handoff.

This is intentional and must remain auditable.

==================================================
8. ATOMICITY / SAFETY
==================================================

The actual warehouse → vehicle transfer must be transactional.

Either:

ALL of the following succeed:

- warehouse deduction
- vehicle addition
- stock movement
- loading completion

OR none of them succeed.

No partial transfer.

Telegram failure must NOT roll back a successfully committed stock transaction.

Use the existing database transaction patterns.

Prevent:
- duplicate confirmation
- double stock deduction
- duplicate vehicle stock
- duplicate labels
- repeated button presses causing duplicate transfer

Use idempotency.
