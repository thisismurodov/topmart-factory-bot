==================================================
5. CONTAINER-LEVEL INVENTORY
==================================================

Every physical production container/location must have its own inventory balance.

Example:

C-20
  → Item A = X kg
  → Item B = Y kg
  → Item C = Z kg

C-19
  → Item A = X kg
  → Item D = Y kg

The same item may exist in multiple containers.

Therefore:

ITEM ≠ CONTAINER

The canonical item identifies WHAT the material/product is.

The container identifies WHERE it physically exists.

==================================================
6. GLOBAL INVENTORY
==================================================

Global inventory must NOT be manually maintained as an independent truth.

For production inventory:

GLOBAL BALANCE
=
SUM(container balances)
+
SUM(WIP balances)

This must be enforceable by the system.

If a material moves:

Container → WIP

global inventory does NOT decrease.

It only changes location.

If WIP → Finished Product:

the relevant material decreases according to BOM/transformation
and finished product increases.

==================================================
7. RAW MATERIAL → WIP → FINISHED PRODUCT
==================================================

The system must support the real manufacturing flow.

Example:

C-01
PP 1500D = 5,000 kg

300 kg is issued to production.

After issue:

C-01 = 4,700 kg
WIP = +300 kg

Later production creates:

50 units of Tulpor
3 kg each

Finished product:

Tulpor = +150 kg

WIP:

300 - 150 = 150 kg

The system must preserve this movement history.

==================================================
8. TRANSFORMATION MUST BE SUPPORTED
==================================================

Some raw materials become intermediate materials before becoming final products.

Example:

PP 1500D
→ twisting
→ twisted PP yarn
→ rope production
→ rope

The intermediate product may itself be:

- sold
- used in another production process
- transferred to another department
- used as BOM material

Therefore the model must support:

RAW
→ INTERMEDIATE
→ FINISHED

and also:

RAW / INTERMEDIATE
→ SALE

==================================================
9. ONE ITEM MAY HAVE MULTIPLE CAPABILITIES
==================================================

Do NOT force every item into exactly one category.

For example PP 1500D can be:

- purchasable
- sellable
- usable as BOM material
- transformable
- inventory-tracked

The canonical item architecture must support capability flags.

==================================================
10. BOM
==================================================

BOM is per one unit of the produced item.

Example:

Tulpor 1 unit
→ 3.000 kg PP 1500D

Hybrid product:

1 finished unit = 3.300 kg

BOM:
PP CF = 1.700 kg
PP BCF = 1.600 kg

The system must allow multiple raw materials in one BOM.

The same raw material can be used by many different products.

BOM must use canonical item IDs, not product names.

==================================================
11. PRODUCTION OUTPUT LOCATION
==================================================

When a production batch is completed, the operator must select a valid finished-goods container/location.

The system must NOT allow a finished product to be accidentally placed into a raw-material-only location.

Container purpose must be enforced.

==================================================
12. SALES MUST CONSUME FINISHED INVENTORY
==================================================

TopMart sales will consume finished-product inventory.

For now, do not redesign the sales system.

The inventory architecture must eventually connect:

SALES
→ FINISHED GOODS INVENTORY
→ CONTAINER BALANCE

without changing existing sales history.

==================================================
13. INVENTORY MOVEMENT AUDIT
==================================================

Every future inventory movement must record:

- item ID
- SKU
- quantity
- unit
- source location
- destination location
- movement type
- user/operator
- timestamp
- reference
- reason where applicable

No silent balance changes.
